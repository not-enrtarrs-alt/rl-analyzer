# Task: Build `rl-analyzer` — Daily Rocket League Trio Tweet Bot

## Objective

Build a Python 3.11+ CLI application in this repository that runs once per day on Windows, finds the most recent eligible 3v3 Rocket League replay where a fixed trio played on the same team using the ballchasing.com API, extracts scoreboard/boost/demo stats, asks a configurable AI provider to write one funny recap tweet, and either posts it to X or delivers it to a file + clipboard. It must never analyze the same match twice and must fail safely.

The app is built from scratch. Build it, test it, document it, and leave it runnable.

## Locked decisions — do not re-litigate

| Area | Decision |
|---|---|
| Language / platform | Python 3.11+, Windows local, SQLite, pytest |
| Trio | One fixed trio, configured by ballchasing profile URLs/IDs, **not** by name |
| Replay selection | Newest replay within a configurable freshness window (default 48h) where all three are on the **same team**, 3v3 only, playlist allow-list |
| Multiple new games | Analyze/post the latest only; leave older games eligible for later runs |
| No new game | Exit quietly, exit code 0 |
| Dedupe | By `match_guid`/`rocket_league_id`, fallback `replay_id`; never call AI twice for the same match |
| AI | Provider-agnostic: Ollama (default), OpenAI, Anthropic, Gemini; plus a `mock` provider for tests |
| Tweet | English, ≤280 weighted characters, emoji allowed, `#RocketLeague` appended, no URLs, no @mentions, no images, no threads/replies |
| Tweet content | Funny recap with light trash talk; mention the standout and roast one underperformer; naming all three is not required |
| Stats | Per-player goals/assists/saves/shots/score/shooting%/demos/boost, plus trio team totals and result/score |
| Posting | X API v2 `POST /2/tweets`; OAuth 1.0a default, OAuth2 bearer fallback; **`POST_TO_X=false` by default** |
| Manual mode | Write `out/tweet.txt`, print it, copy to clipboard |
| Schedule | Windows Task Scheduler daily at **19:00 local** |
| Rate guard | 20-hour cooldown between successful posts/generations; `--force` overrides |
| AI failure | One shorten retry; then skip posting. **No template fallback.** |
| Post failure | Keep generated text and retry posting next run without re-analyzing |
| Docs | Full resumable docs: `PLAN`, `PROGRESS`, `DECISIONS`, `HANDOFF`, `TOOLNOTES`, `SPEC`, setup guides |

## Data model

SQLite with idempotent schema creation and a `meta` table for `schema_version`.

```sql
CREATE TABLE IF NOT EXISTS replays (
  replay_id TEXT PRIMARY KEY,
  match_key TEXT NOT NULL,          -- match_guid, else rocket_league_id, else replay_id
  match_guid TEXT,
  rocket_league_id TEXT,
  match_date TEXT NOT NULL,         -- UTC ISO 8601
  status TEXT NOT NULL,             -- generated | posting | posted | skipped | analysis_failed
  tweet_text TEXT,
  tweet_id TEXT,
  reason TEXT,
  attempts INTEGER NOT NULL DEFAULT 0,
  provider TEXT,
  model TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  posted_at TEXT
);

CREATE INDEX IF NOT EXISTS idx_replays_match_key ON replays(match_key);
CREATE INDEX IF NOT EXISTS idx_replays_status ON replays(status);
CREATE INDEX IF NOT EXISTS idx_replays_match_date ON replays(match_date);

CREATE TABLE IF NOT EXISTS posts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  replay_id TEXT NOT NULL,
  tweet_id TEXT,
  text TEXT NOT NULL,
  posted_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

Rules:

- `match_key` is the canonical dedupe key. Same match uploaded twice with different replay IDs must not be analyzed twice.
- `generated` means a valid tweet exists but has not been posted live. `posted` means live post succeeded. `posting` is an in-flight guard.
- `analysis_failed` rows may be retried only while `attempts < 2`; then mark `skipped` with `reason=ai_failed`.
- `skipped` is terminal; reasons include `expired`, `duplicate_match`, `posting_unknown`, `ai_failed`.
- Store `meta.last_success_at` after a successful live post or manual delivery. Cooldown is based on the later of `meta.last_success_at` and the latest `posts.posted_at`.
- Never store duplicate `posts` rows for the same tweet.

## Pipeline

Implement `python -m rl_analyzer run` as:

1. Acquire a lock file `data/run.lock` (atomic create, write PID/time). If a fresh lock exists, exit 0 with a log message. Remove the lock on exit. Remove stale locks older than 2 hours.
2. Load and validate config. Initialize DB and logging.
3. **Cooldown:** if `now - last_success_at < COOLDOWN_HOURS` and `--force` was not passed, log and exit 0.
4. **Pending live post:** if `POST_TO_X=true`, look for the newest row with `status=generated`. If it exists:
   - If still within the freshness window, attempt to post the cached `tweet_text`; do not call the AI again.
   - On success, mark `posted`, record the post, set `last_success_at`, deliver a copy to `out/`, exit 0.
   - On failure, leave `generated`, log, exit 5.
   - If expired, mark `skipped` with `reason=expired_before_post` and continue.
5. **Select a candidate** using the algorithm below. If none, log and exit 0.
6. Fetch replay detail and extract stats. Validate; if invalid, skip and try the next candidate up to the cap.
7. Build the AI payload and call the configured provider.
8. Sanitize, validate, and finalize the tweet. If invalid after one shorten retry, mark `analysis_failed` and exit 4. Do not post a template.
9. Persist a `generated` row with the exact final text before attempting delivery.
10. If `POST_TO_X=true`: set `status=posting`, post, then mark `posted` and set `last_success_at`. On failure, set back to `generated`, log, exit 5.
11. If manual mode (`POST_TO_X=false`): write files, copy to clipboard, set `last_success_at`, leave `generated`, exit 0.
12. `--dry-run` performs steps 2, 5–8, then delivers to file/clipboard/console **without writing DB or posting**, and without cooldown.

`preview` is like `--dry-run` but may accept `--replay-id` to inspect a specific replay. It never writes DB or posts.

`demo` runs the full extraction/finalization/delivery path against `tests/fixtures/replay_detail.json` with the `mock` AI provider, no network, no DB, and writes `out/demo_tweet.txt`. It must work with no `.env` and no credentials.

## Ballchasing API contract

Base URL: `https://ballchasing.com/api`.

Authentication header:

```
Authorization: <BALLCHASING_TOKEN>
```

Do **not** prefix with `Bearer`.

### List/filter replays

```
GET /replays
  ?player-id=<platform:id>
  &replay-date-after=<RFC3339 UTC>
  &count=200
  &sort-by=replay-date
  &sort-dir=desc
```

Query each of the three players **separately**, then intersect replay IDs client-side. This avoids ambiguity about multiple `player-id` filter semantics. Throttle at least `BALLCHASING_MIN_INTERVAL_SECONDS` between requests.

Response shape:

```json
{
  "count": 7,
  "list": [
    {
      "id": "969c37e6-f5c7-41bf-a0c0-21922df74469",
      "date": "2021-04-12T01:26:47+02:00",
      "playlist_id": "private",
      "playlist_name": "Private",
      "duration": 394,
      "overtime": true,
      "map_name": "Utopia Coliseum (Dusk)",
      "blue": {
        "name": "TEAM ENVY",
        "goals": 1,
        "players": [
          { "name": "mist", "id": { "platform": "steam", "id": "76561198245238200" }, "score": 526 }
        ]
      },
      "orange": { "...": "same shape" }
    }
  ]
}
```

### Replay detail

```
GET /replays/{id}
```

Important fields and paths:

- `id`, `match_guid`, `rocket_league_id`, `date`, `created`
- `status` — require `"ok"`
- `team_size` — require `3`
- `playlist_id`, `playlist_name`
- `map_name`, `duration`, `play_duration`, `overtime`, `overtime_seconds`
- `blue` / `orange`, each with:
  - `name`
  - `players[]` with `name`, `id.platform`, `id.id`, `mvp` (may also be in `stats.core.mvp`)
  - `stats.core` — `goals`, `assists`, `saves`, `shots`, `score`, `shooting_percentage`, `mvp`
  - `stats.boost` — `bpm`, `avg_amount`, `time_zero_boost`
  - `stats.demo` — `inflicted`, `taken`
  - `stats` team totals — same `core`, `boost`, `demo` paths

Rate limits: 2 requests/second, 500 list requests/hour, 1000 detail requests/hour for non-patrons. Implement a shared throttle and retry on 429/5xx with exponential backoff (1s, 2s, 4s) and `Retry-After` support. Handle 401/403 with a clear "check BALLCHASING_TOKEN" error.

Do not download replay files. Use only the JSON stats endpoints.

## Selection algorithm

1. `cutoff = now_utc - MAX_REPLAY_AGE_HOURS`.
2. Fetch each player's replays with `replay-date-after=cutoff`, `count=200`, sorted newest first.
3. Intersect replay IDs across all three lists. A replay must appear in all three.
4. Remove replays already consumed in the DB:
   - `generated`, `posting`, `posted`, `skipped` are consumed.
   - `analysis_failed` is consumed only if `attempts >= 2`.
5. Remove replays whose `match_key` is already consumed by another row.
6. Sort candidates by `date` descending.
7. Inspect up to `MAX_CANDIDATES_TO_INSPECT` candidates by fetching detail. A candidate is eligible only if:
   - `status == "ok"`
   - `team_size == 3`
   - `playlist_id` is in `ALLOWED_PLAYLISTS`
   - all three normalized player IDs are in the **same** team (`blue.players` or `orange.players`)
   - `date` is within the freshness window
   - required core stats exist
8. Select the newest eligible candidate. If none, exit 0 quietly.
9. Do **not** mark older unposted games as skipped. They remain eligible until they fall outside the freshness window.
10. If a candidate is a duplicate upload of a consumed match, record that replay as `skipped` with `reason=duplicate_match` and continue.

Date handling: parse ISO 8601 with offset. If the date is naive, assume UTC and log a warning. Compare in UTC. Store `match_date` as UTC ISO 8601.

Rules:

- If a stat is missing, use `null` and instruct the AI not to mention it.
- Do not include opponents' names or stats in the payload.

## AI contract

Create a provider interface:

```python
class AIProvider:
    def generate(self, system: str, user: str) -> str: ...
```

Providers:

- **Ollama**: `POST {OLLAMA_BASE_URL}/api/chat` with `{"model": ..., "messages": [...], "stream": false, "options": {"temperature": ..., "num_predict": ...}}`.
- **OpenAI**: `POST {OPENAI_BASE_URL}/chat/completions`.
- **Anthropic**: `POST https://api.anthropic.com/v1/messages` with `x-api-key` and `anthropic-version`.
- **Gemini**: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key=...`.
- **Mock**: deterministic, test-only provider. Never used as a fallback.

System prompt requirements:

> You write ONE tweet in English recapping a Rocket League match for a private friend group. Voice: funny recap with light, playful trash talk. Use only the stats in the JSON. Never invent numbers. Mention the result and score. Name the standout player and roast one underperformer using the provided aliases. Include at least one boost or demo stat. Keep it under 240 weighted characters; emoji count as 2. Use at most 2 emoji. Do not use hashtags, @mentions, URLs, line breaks, quotes, or markdown. Do not name opponents. Do not write anything except the tweet text.

User prompt: the stats JSON above, then a short instruction to write the tweet now.

Provider behavior:

- Temperature `AI_TEMPERATURE`; max output tokens `AI_MAX_OUTPUT_TOKENS`.
- Retry 429/5xx with backoff; do not retry 400/401/403.
- Raise a typed `AIError` on failure.
- Never include secrets in errors.
- The `mock` provider returns a valid canned tweet built from the payload, for tests and `demo` only.

## Tweet rules and validation

Finalization steps:

1. Strip Markdown fences, surrounding quotes/backticks, and preambles such as `Tweet:` or `Here is your tweet:`.
2. Collapse all whitespace and newlines to single spaces.
3. Remove URLs.
4. Remove `@mentions`.
5. Remove all hashtags; append exactly one configured hashtag at the end with one space.
6. Trim to a single trailing punctuation mark if duplicated.
7. Reject empty output, refusals (`I can't`, `I cannot`, `I'm sorry` at the start), or output under 20 characters.
8. Enforce `≤ TWEET_MAX_WEIGHTED_LEN` using a conservative weighted counter: most characters 1, emoji and CJK 2, URLs 23. Because URLs are removed, only emoji/CJK matter.
9. Require the score string `"<trio>-<opponents>"` (for example `3-2`) to appear in the text. If missing, retry once.
10. Require at least one configured alias or replay name to appear. If missing, retry once.
11. If the tweet is over length, retry once with a shorter instruction. If still invalid, mark `analysis_failed` and do not post.
12. Do not add a template fallback.

Emoji: allow at most 2. Instruct the AI accordingly. Do not fail solely on emoji count, but strip extras if easy.

## X posting

Implement `XClient.post(text) -> tweet_id`.

- Endpoint: `POST {X_API_BASE_URL}/2/tweets` with JSON `{"text": text}`.
- OAuth 1.0a default using `requests-oauthlib.OAuth1Session` with `X_API_KEY`, `X_API_SECRET`, `X_ACCESS_TOKEN`, `X_ACCESS_SECRET`.
- OAuth2 fallback: `X_AUTH_MODE=oauth2` with `X_OAUTH2_USER_TOKEN` sent as a Bearer token. Tokens expire; document manual refresh.
- Success: HTTP 201 with `{"data": {"id": "..."}}`.
- Handle 401/403, 429, and 5xx with clear errors. Do not retry a post automatically inside the same run; leave the replay `generated` for the next run.
- Never log tokens or the Authorization header.
- No media upload, no replies, no threads, no quote posts.
- Do not add URLs to tweets. As of 2026, X charges `$0.015` per text post and `$0.20` per post containing a URL; there is no free tier for new developers. One text-only post/day is roughly `$0.45/month`. Verify current pricing in `docs/SETUP_X.md`; do not hardcode prices in code.

## Manual delivery

When `POST_TO_X=false` or `--dry-run`:

- Write `out/tweet.txt` (UTF-8, no BOM) containing only the final tweet text.
- Write `out/last_run.json` with metadata: replay ID, match key, match URL, match date, result, score, provider, model, timestamps, status. No secrets.

- Print the tweet to the console in a readable block.

- On live success, also archive the posted text under `out/posted/`.

## Cooldown, dedupe, and failure handling

- Cooldown: `COOLDOWN_HOURS` (default 20) since `meta.last_success_at` or the latest live post. Bypassed by `--force`.
- `--dry-run` and `preview` bypass cooldown and do not mutate DB.
- Dedupe by `match_key`, not just `replay_id`.
- A consumed match must never trigger another AI call.
- If a `generated` row exists and is still fresh, reuse its `tweet_text`; never regenerate.
- If a `generated` row is expired, mark `skipped` and move on.
- If a post fails, leave the row `generated` and exit 5.
- If the process crashes mid-post, a `posting` row must block automatic reposting. Log a warning and require manual inspection; `doctor` must report it.
- AI failure or over-length output: mark `analysis_failed`, increment attempts, do not post. Retry next run only while attempts < 2; then `skipped`.
- No new eligible replay: exit 0 and log clearly.
- Exit codes: `0` success/no-op, `2` config error, `3` ballchasing error, `4` AI error, `5` posting error, `6` lock/unknown.

- Config: parse raw IDs and profile URLs; normalize platforms; reject duplicates/names/unknown platforms; provider credential validation.
- Ballchasing: auth header, query params, per-player intersection, throttling, 429/5xx retry, 401 mapping.
- Selection: newest eligible; 2v2 rejected; split-team rejected; wrong playlist rejected; old replay rejected; duplicate `match_key` skipped; older backlog not marked.
- Stats: correct team identification, score/result, per-player mapping, team totals, missing stats, standout/underperformer.
- Tweet: weighted length with emoji/CJK; hashtag appended exactly once; URLs/@/Markdown stripped; over-length retry; refusal detection; score/alias validation.
- Store: schema idempotency, status transitions, dedupe by `match_key`, cooldown, pending `generated` reuse, `analysis_failed` retry cap, `posting` guard.
- AI: prompt contains stats; request payloads for Ollama/OpenAI/Anthropic/Gemini; mock provider; error mapping; no secrets in logs.
- X: OAuth1 signing (mock), bearer fallback, 201 success, 401/429/5xx errors.
- Delivery: files written, UTF-8, clipboard called, history archive.
- Pipeline: no candidate → no AI call; posted match never analyzed; AI failure → no post and no template; post failure → cached text reused next run; cooldown blocks; dry-run no DB writes; `demo` works offline.

Add `tests/fixtures/replay_detail.json` with a realistic 3v3 replay containing three players whose IDs match the test config. Add `replay_2v2.json` and `replay_split_team.json` for rejection tests.

## Definition of done

- `pytest -q` passes with no network access.
- `python -m rl_analyzer demo` produces `out/demo_tweet.txt` and a valid ≤280-character tweet.
- `python -m rl_analyzer doctor --offline` gives a clear report; missing credentials are warnings.
- `python -m rl_analyzer preview` works with a valid ballchasing token and either Ollama or a mock provider.
- The scheduled task installer is idempotent and documented.
- Every requirement maps to code or a documented limitation.
- No secrets, real IDs, or tokens are committed.
- No live X posts occurred during development.
- `docs/PROGRESS.md` and `docs/HANDOFF.md` are current.

## Do not

- Do not post to X during development. `POST_TO_X` stays `false` unless the user explicitly asks for a live test.
- Do not commit `.env`, `data/`, `logs/`, or `out/`; add them to `.gitignore`.
- Do not use real player IDs, tokens, API keys, or handles; `.env.example` uses placeholders only.
- Do not resolve players by display name or search; use the configured ballchasing profile IDs.
- Do not analyze, generate, or post twice for the same `match_key`.
- Do not add URLs, @mentions, images, threads, replies, or quote posts.
- Do not use a template fallback when AI generation fails; skip instead.
- Do not invent, estimate, or round up stats. Use only the JSON payload.
- Do not exceed 280 weighted characters or post unvalidated text.
- Do not post more than once per cooldown unless `--force` is passed.
- Do not mark older unposted games as skipped; keep the backlog.
- Do not add a web UI, HTTP server, database server, async workers, or Docker.
- Do not download or parse replay files; use the ballchasing JSON API only.
- Do not hardcode model IDs, API base URLs, prices, or credentials; keep them configurable.
- Do not end a turn immediately after a tool call.
- Do not recreate, restructure, or overwrite working code on resume.
- Do not add features outside this spec.

## Handoff protocol

- Write `docs/HANDOFF.md` containing:
  - Last completed milestone and acceptance result.
  - What is verified vs. untested.
  - Known bugs with file/function names.
  - Deviations from this spec and why.
  - Conventions the next agent must follow.
  - Exact next step and the files it will touch.
- Update `docs/PROGRESS.md`.
- Do not start a new milestone.

## First-run checklist for the human

1. Copy `.env.example` to `.env`.
2. Fill `BALLCHASING_TOKEN`, the three player IDs, and aliases.
3. Install Ollama and run `ollama pull llama3.1:8b`, or configure another provider.
4. Run `python -m rl_analyzer doctor`.
5. Run `python -m rl_analyzer preview` and inspect `out/tweet.txt`.
6. To post live, follow `docs/SETUP_X.md`, set `POST_TO_X=true`, and run once with `--force`.
7. Install the daily task: `powershell -ExecutionPolicy Bypass -File scripts/install_task.ps1`.

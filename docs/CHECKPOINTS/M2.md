## Known limitations

- Store is not yet wired into a pipeline. `run`, `preview`, `demo` and `history` are CLI skeletons, and no AI or posting implementation exists. M4 must use the reservation and read-only interfaces described in `HANDOFF.md`.
- A crash during AI analysis leaves a guarded `analysis_in_progress` reservation, requiring inspection; ambiguous post outcomes remain `posting` instead of being automatically retried. These are deliberate safety choices documented in `DECISIONS.md`.
- Three nullable result/score columns were added beyond the supplied schema so future history can report the required fields; older version-1 databases gain them idempotently.
- No authenticated API calls or X posts were made. No Task Scheduler task was installed.
